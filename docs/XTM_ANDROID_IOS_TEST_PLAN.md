# XTM Android + iOS compatibility test plan

Status: planned. This audit did not install an APK/IPA, connect a phone, unlock a wallet, sign a challenge, or submit a transaction. All automated checks below use synthetic data or dedicated testnet wallets.

## Preconditions and fixture policy

- Use a dedicated testnet/nextnet wallet with no valued funds and a local/pinned test base node.
- Record app build, FFI version, device OS/model, selected network, node tip height/hash, and protocol-capability version for every run.
- Never export unblinded outputs, masks, script keys, view keys, seeds, or recovery material to a test log. The current core warning explains why old private-key UTXO exports are unsafe. [Source](https://github.com/tari-project/tari/blob/059491ce35fbe0b45abefb32332cf372cd4a8f1c/applications/minotari_console_wallet/README.md).
- Test a proposed proof API only after it has an approved threat model and a non-production build flag.

## Existing deep-link compatibility

| ID | Input/action | Android expected result | iOS expected result | Pass criterion |
|---|---|---|---|---|
| DL-01 | `tari://<active-network>/transactions/send` with synthetic valid address, no amount | Opens normal send form; recipient prefilled | Opens normal send form; recipient prefilled | No send/broadcast occurs without a later explicit confirmation. |
| DL-02 | Same URI with valid amount/note | Amount/note prefilled | Amount/note prefilled | MicroTari amount round-trips as an integer; no JS/float conversion. |
| DL-03 | Syntactically valid but different network | Rejected/no navigation (source already checks current network) | Must be rejected after upstream fix | Network mismatch has a specific user-visible message and no payment form. |
| DL-04 | Wrong scheme, command, missing address, negative/overflow amount, duplicate params | Rejected safely | Rejected safely | No crash, silent network substitution, or malformed transaction draft. |
| DL-05 | URI arrives while wallet locked/not ready | Deferred or clear locked/not-ready state | Deferred or clear locked/not-ready state | No automatic action after unlock without review. |
| DL-06 | `paper_wallet` and airdrop/recovery links | Existing dedicated warning/recovery UX only | Existing dedicated warning/recovery UX only | They cannot be interpreted as proof or payment requests. |

Run the current source unit tests around the Android parser and iOS `DeepLinkFormatterTests`; add iOS test coverage for `mainnet` URI while `testnet` is selected. The source route references are [Android](https://github.com/tari-project/wallet-android/blob/0d4c15c94bfdf44df9e4b3721374fa82fdf4d21b/app/src/main/java/com/tari/android/wallet/application/deeplinks/DeeplinkParser.kt) and [iOS](https://github.com/tari-project/wallet-ios/blob/e01cc1e9f14eaaf04c93202ac7a53bcf82d40b04/UnitTests/DeepLinkFormatterTests.swift).

## Proposed proof-API test matrix

| ID | Scenario | Expected outcome |
|---|---|---|
| PF-01 | Well-formed challenge on active network with a qualifying dedicated test output | Wallet displays origin, expiry, threshold, disclosure; user approval yields independently verifiable proof. |
| PF-02 | User rejects, app locked, biometric/PIN fails | Distinct rejection/locked result; no proof bytes or output identifiers returned. |
| PF-03 | Challenge replay, nonce mutation, different origin/callback, expired challenge | Verifier rejects; wallet does not silently reissue a proof. |
| PF-04 | Different genesis/network or changed active network | Fail before output selection. |
| PF-05 | No eligible output, output encumbered/spent, offline/not synced | Explicit non-proof status; never substitutes aggregate balance. |
| PF-06 | Threshold boundary: one microTari below/equal/above | Below fails; equal/above follow protocol; verifier detects all tampering. |
| PF-07 | Reorg and stale-tip simulation | Verifier rejects/requests fresh proof according to published finality policy. |
| PF-08 | Device/app switch, callback interception, malicious RP label | Callback/RP binding fails; approval screen exposes canonical RP identity. |
| PF-09 | Android ↔ iOS cross-verification | A proof generated by either implementation verifies identically against the same test vector. |
| PF-10 | Ledger/desktop paired transport | Visible pairing plus per-request device review; no ambient localhost authorization. |

## Release and regression checks

1. CI checks the mobile FFI archive/header against the wrapper functions. Fail if a removed sensitive API such as `wallet_get_unspent_outputs` is still called.
2. CI allows only audited FFI versions. The inspected Android/iOS source pins 6.1.0 whereas the current core release is 6.2.0; resolve that upgrade/security review before marketing an L1 proof feature. [v6.2.0](https://github.com/tari-project/tari/releases/tag/v6.2.0).
3. Fuzz URI decoding with percent encoding, duplicate keys, large notes, Unicode, and maximum `UInt64` amounts.
4. Use known-answer proof vectors across Kotlin/JNI, Swift/XCFramework, Rust verifier, and Ledger transport.
5. Confirm telemetry/log redaction by searching fixture logs for keys, seeds, unblinded JSON, challenge secrets, and full output references.
6. Repeat on a clean install, an upgraded wallet database, restored wallet, and an external/seedless Universe configuration.

## Acceptance rule

No mobile/desktop wallet is marked “XTM Ghost Gate supported” until every critical case above passes on released binaries, an independent verifier accepts only valid proofs, and privacy review confirms that the transcript reveals no more than the documented threshold relation and one-time proof linkage.
