04Mainnet Admission Blockers

The following must be resolved before mainnet admissions can be enabled. These are implementation tasks, not accepted limitations.

  • Mainnet resource address (TARI)

    The on-chain resource address for TARI on Ootle mainnet has not been published. The gate policy cannot be configured without it. Do not substitute an Esmeralda testnet address.

  • Ootle cohort upgrade (v0.42 → v0.52)

    Ghost Gate's Rust workspace pins to the v0.42.0 Ootle tree. sr25519 signing (v0.48) and template V2 (v0.50) are breaking changes. The upgrade requires a new cohort checkout, template rebuild, walletd client update, and full test suite pass.

  • Mainnet indexer and walletd endpoints

    The mainnet Ootle indexer URL and walletd binary/endpoint are not yet published by Tari Labs. ootle.ts v0.14.0 notes that defaultIndexerUrl throws for mainnet. The bridge configuration requires these before any proof attempt.

  • M3 High security findings (identity binding, restart recovery, admin isolation)

    Three unresolved High findings documented in docs/SECURITY_M3_REVIEW_STATUS.md must be resolved before Telegram admission can be enabled on any network, including mainnet. These affect all admission paths, not only Esmeralda.

  • Telegram admission testing against mainnet infrastructure

    End-to-end admission testing requires a live mainnet wallet producing an authenticated credential proof against a real mainnet gate. No synthetic shortcut is acceptable for the final pre-activation check.
